# 06 · 踩坑 FAQ

全部为本机真踩过的坑，按疼的程度排序。

## 1. "Model Initializing" 卡死 27 分钟

**现象**：进程活着，日志停在模型初始化，27 分钟不动。而正常情况下采样一步只有 91 秒——瓶颈根本不在 GPU。

**根因**：12.5G 模型文件的磁盘加载 + staging 是 I/O 密集操作，被**杀毒软件的实时防护**逐块扫描拖慢（本机案例为某款第三方安全软件，不点名；任何开启主动防御的杀软均有可能）。

**解法**：跑渲染前手动关闭杀软实时防护，跑完再开。长跑批任务额外配"检测卡死 → 干净重启 → 断点续跑"兜底（按图快照同种子重提）。

## 2. prompt_id 相同的重提被静默丢弃

**现象**：崩溃后重提同一个工作流，ComfyUI 悄悄不执行，也没有报错。

**根因**：H3 的 prompt_id 按**输入内容确定性生成**，输入不变 id 不变，前端会认为任务已存在。

**解法**：断点续跑时改一个无关节点值（如 seed+1）让输入变化；或清理历史 manifest 后重提。

## 3. ComfyUI 关停时队列残留

**现象**：进程被杀后，重启发现之前队列里的任务"复活"继续跑。

**根因**：队列状态持久化在磁盘，重启自动恢复。算力被意外占用时先查这里。

**解法**：想让重启后是干净状态，关停前清空队列；`.submit.claim` 并发锁文件在进程崩溃后可能残留，会挡住新提交——手动清理。

## 4. T8 BlockCache 节点注册失败

`MiniMaxH3BlockCacheT8` 在 sm_75 环境注册失败：依赖 ComfyUI v3 Layers API，且加速内核面向新架构。**Turing 上放弃这个节点**，compat 工作流已经绕开（详见 [01](01-hardware-limits.md)、[07](07-upgrade-watch.md)）。

## 5. aria2 下载的模型文件"幽灵消失"

**现象**：aria2 下载显示完成，文件过一会儿没了。

**根因**：特定沙箱/安全软件环境会静默删除 aria2 的临时下载文件（`.aria2` 控制文件 + 未落盘数据）。

**解法**：大文件用 Python 分块下载器（requests + 断点续传），稳定得多。本机 12.5G+ 模型全部改走这条路。

## 6. pinned memory 的 read_file_slice OOM

启动日志出现 `read_file_slice` 相关失败后 OOM。解法：启动参数直接 `--disable-pinned-memory`，无副作用，见启动模板。

## 7. 共享桌面 GPU 的 TDR 黑屏

ComfyUI 和桌面共用 2080Ti 时，显存吃紧会触发驱动 TDR 复位（屏幕黑一下，任务死亡）。解法：`--reserve-vram 2.5 --vram-headroom 0.5` 留足桌面余量，见启动模板。

## 8. KJNodes 里藏着一个没启用的宝贝

翻 KJNodes 源码发现内置了 `MiniMaxH3MemoryEfficientSageAttentionPatch`（fused qkv + RMSRoPE，只补丁 DiT 自注意力）——这是 H3 专属的原生 Sage 补丁，理论上兼容性比第三方 PatchSageAttentionKJ 好。**截至本文尚未在 sm_75 验证通过**，挂在待测清单里（见 [07](07-upgrade-watch.md)）。

## 9. TE-Speed 能装能跑，但作品报废

**现象**：TE-Speed（文本编码器加速）安装运行无报错，速度确实有提升，于是容易误判为可用。

**根因**：H3 走 4 步 Turbo 快路线，步数本来就极少，TE-Speed 的有损压缩在这个短步数下直接造成**语义崩坏**——生成的画面与提示词脱钩。

**结论**：**永久排除**，不是版本问题，等新版也救不回来。想提速请看 [07](07-upgrade-watch.md) 的路线全景，别在这条路上花时间。

## 10. 原生音频会削波吗？

不会，实测可以放心。ffmpeg `volumedetect`/`astats` 检查生成样片：

- 正常样片：mean −14.0dB，**max −0.6dB**（离削波还有余量）
- 个别偏响样片：mean −25.7dB，max −10.2dB

无需救火。成片流程统一挂一个 **−1dB limiter** 兜底即可。另：v0.33.1 已内置原生 AV 采样修复（commit `bdcb886`），如遇爆音先确认版本，别急着上 DualClockSampler 之类的修复插件。

## 11. v3 API 节点用 /prompt 提交报 400

**现象**：`MiniMaxH3BlockCacheT8` 等新式节点（v3 `comfy_entrypoint` 协议）在 ComfyUI 界面里能正常用，但走 `/prompt` API 提交就 400，报一堆 `required_input_missing`，连 `advanced: True` 的参数都算缺。

**根因**：**v3 节点不走服务端默认值**——schema 里声明的每个输入都必须在提交 JSON 里显式给值，一个都不能省。v2 老节点没这个坑，所以网上老教程查不到答案。

**解法**：把节点的全部输入（含 advanced 项）显式写进 API JSON。本仓库 [workflows/](../workflows/README.md) 的草稿档工作流已全部显式化，可直接参考。

## 12. 缓存类加速节点会让「同 seed 重跑」失灵

**现象**：开了 T8 BlockCache 等缓存类加速后，同 seed 同参数重跑，出来的**不是同一条片**；依赖「失败镜头原样重提」的断点续跑策略全部失效。

**根因**：不是 bug——缓存命中复用了上一步残差，数值轨迹从此分叉，同 seed 走的是不同采样路径。产出是**同质量的不同画面**（实测帧差 PSNR 14dB 级但目检无任何劣化，见 [08](08-t8-blockcache-4step.md)）。

**解法**：分档使用——草稿/选镜头用加速档（快 43%），成片镜头用无缓存基线档保可复现性。`workflows/` 三件套已按此分工。

## 13. ComfyUI 空闲一段时间自动退出，跑批半夜全灭

**现象**：挂机批量渲染，早上回来发现 ComfyUI 进程不知何时退了，队列停在中途。

**根因**：某些构建/环境下 ComfyUI 空闲后会自退进程（v0.33.1 实测存在）；桌面会话锁定、显存驱动复位也可能触发。

**解法**：长跑批**必须**自带看门狗——「检测进程死亡 → 干净重启 → 按图快照同种子补提交」三件套逻辑，别裸挂。提交前保存 graph 快照，重启后按快照重提即可断点续跑（注意：用了缓存加速节点的任务重提结果会变，见上一条）。
