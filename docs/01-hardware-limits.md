# 01 · 2080Ti 22G 的先天限制

先搞清楚这张卡缺什么，才能理解为什么有些路线走不通——**不是你没调好，是硬件没有那块电路**。

## 架构账

| 项目 | 2080Ti 22G 魔改 | 3090 | 4090 |
|---|---|---|---|
| 架构 / 计算能力 | Turing / **sm_75** | Ampere / sm_86 | Ada / sm_89 |
| 显存 | 22G（魔改） | 24G | 24G |
| 显存带宽 | 616 GB/s | 936 GB/s | 1008 GB/s |
| BF16 / FP8 张量核心 | ❌ 无 | ✅ / ❌ | ✅ / ✅ |

带宽差距是物理天花板：视频生成的 DiT 前向是访存密集型，616 GB/s 意味着同参数下天生比 3090 慢约 1.5 倍，比 4090 慢 2 倍以上。**这条不要试图"优化"掉，只能力逼近**。

## 先说一张你已经中奖的彩票：cu130 硬件反量化

带宽账算完像绝境，但 Turing 用户手里其实已经捏着一项红利——**torch 2.9.1+cu130 会把 comfy-kitchen 的 CUDA 反量化后端满血启用**（`w4a8_int8_linear`、`dequantize` 全套 capability 可用），W4A8 权重的反量化走硬件指令而非软件回退路径。

这是本手册实测速度（约 5.7 分钟/镜）与官方手册 20-30 分钟之间差距的根因——不是调参调出来的，是运行时版本决定的。neng320/minimax-h3-local-deployment 社区手册同法验证过 480p 3-5 分钟/条。

**推论**：如果你在老版 torch/cu121/cu124 上跑 W4A8 慢得离谱，先查运行时，再怀疑显卡。

## 对 H3 的三个直接影响

### 1. SageAttention / T8 加速内核面向 SM80+

SageAttention 的 Triton 内核和 T8 双时钟采样器（BlockCache）的优化路径以新一代架构为目标。在 sm_75 上：

- T8 BlockCache 节点直接注册失败（依赖 ComfyUI v3 Layers API，且设计目标不含 Turing）
- SageAttention 孤立内核能编译，但接进 H3 管线触发原生崩溃（详见 [03](03-sageattention-crash.md)）

**结论：加速节点路线在 sm_75 上放弃，走 compat 版工作流。**

### 2. DiT 必须跑 INT8（W4A8）

社区实测数据（同款 2080Ti 22G 卡）：

- W4A4 权重激活双 4bit：重建误差 **0.2005**
- W4A8（激活 INT8）：重建误差 **0.0110**

18 倍的误差差距，直接体现在画面上——W4A4 出**彩色撕裂**。H3 官方发布的 W4A8 mixed 权重就是这张卡的唯一可用形态。

### 3. 显存刚好够，但要管好

INT8 DiT 常驻约 19.5G，22G 显存余量只有 2.5G 左右，所以：

- 桌面共享 GPU 时要防 TDR 黑屏（`--reserve-vram 2.5 --vram-headroom 0.5`）
- pinned memory 的 `read_file_slice` 失败路径会引发 OOM，直接 `--disable-pinned-memory` 关掉
- 别在这个卡上同时开着浏览器看 4K 视频

## h3lite 仓库没有 2080 专属 issue

截至本文，h3lite 仓库没有 2080Ti 用户报告专属问题——侧面说明 **compat + W4A8 大概率已经是这张卡的最优解**，不用再找"隐藏的正确姿势"。
